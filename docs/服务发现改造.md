# 服务发现改造（登录服）

总规则见 [service-discovery.md](service-discovery.md)，本文是登录服这一侧的改动清单和验收项。

改造后登录服是 zfoo **provider**：游戏服自动连上来并上报自己的信息，登录服按上报维护「区 → 游戏服」表，登录时从表里取游戏服地址。登录服不再监听 ZooKeeper，也不再注册自己的节点。

## 1. 删除

| 内容 | 说明 |
| --- | --- |
| `service/ServiceDiscoveryService` | 不再监听 `/danmu/<appKey>/logic`，不再写 `/danmu/<appKey>/login/<地址>` |
| `pojo/ServerNode` | 只有发现逻辑使用 |
| `Application` 中 `ServiceDiscoveryService.start()` 调用 | |
| `server.public-host`、`server.inner-host` 配置及 `ApplicationProperties` 对应字段 | 只用于写登录服自身节点；删除前确认没有其他引用 |

## 2. 配置

### 2.1 config.xml

```xml
<net:net id="${server.node-id}" protocol-location="protocol.xml">
    <net:registry center="zookeeper" path="/danmu/${app.key}" user="" password="">
        <net:address name="zookeeper" url="${zookeeper.address}"/>
    </net:registry>
    <net:providers>
        <net:provider protocol-module="login" provider="${server.service-name}"/>
    </net:providers>
</net:net>
```

- `id` 原来写死为 `deepSeaWar`，改为 `${server.node-id}`。
- `path` 原来没有配置（zfoo 默认 `/zfoo`），改为 `/danmu/${app.key}`。
- 协议模块 `login`（登录服自己的模块）、服务名 `loginReport`，节点名中显示为 `login-loginReport`；回调服是另一个独立的提供方（`callback-callbackReport`）。
- provider 不配 `address`：zfoo 取本机地址，端口从 12400 起找可用端口，自动启动 provider 的 TcpServer（与对外 HTTP 端口无关）。

### 2.2 protocol.xml

`login` 模块号由 3 改为 5（与游戏服一致，游戏服的 3 号是 `game`），协议号按模块号 × 1000 重排，上报协议在前：

```xml
<module id="5" name="login">
    <protocol location="com.oaixdog.loginserver.protocol.LoginReport"/>        <!-- 5000 -->
    <protocol location="com.oaixdog.loginserver.protocol.LoginReportAnswer"/>  <!-- 5001 -->
    <protocol location="com.oaixdog.loginserver.protocol.LoginRequest"/>       <!-- 5002，原 1000 -->
    <protocol location="com.oaixdog.loginserver.protocol.VersionRequest"/>     <!-- 5003，原 1001 -->
    <protocol location="com.oaixdog.loginserver.protocol.LoginResponse"/>      <!-- 5004，原 1002 -->
    <protocol location="com.oaixdog.loginserver.protocol.VersionResponse"/>    <!-- 5005，原 1003 -->
</module>
```

HTTP 协议走 JSON 路由，协议号不在网络上传输，改号不影响客户端。

### 2.3 application.properties

```properties
# 节点 ID，多台登录服各不相同：login-1、login-2
server.node-id=login-1
# 服务名，与游戏服的 login.service-name 一致
server.service-name=loginReport
```

## 3. 新增

### 3.1 协议类（包 `protocol`，登录服自己的协议对象，与回调服的 `CallbackReport` 无关）

- `LoginReport`：`@Protocol(id = 5000)`，字段依次为 `int serverId`、`String instanceId`、`String host`、`int port`、`String innerHost`、`int gmPort`。
- `LoginReportAnswer`：`@Protocol(id = 5001)`，字段依次为 `boolean accepted`、`String message`。

### 3.2 `LoginReportController`

```java
@PacketReceiver
public void atLoginReport(Session session, LoginReport report, SignalAttachment attachment)
```

调用 `ZoneService.report(session, report)`，把结果用 `NetContext.getRouter().send(session, answer, attachment)` 回复。

### 3.3 `ZoneService`

内存表 `ConcurrentHashMap<Integer, Zone>`，`Zone = { LoginReport report, Session session, long reportTime }`。

- `report(session, report)`（同一区的判断和写入要原子，例如用 `compute`）：
  1. 没有记录，或已有记录 `instanceId` 与本次相同 → 覆盖（含 `session`、`reportTime=当前时间`），接受。
  2. `instanceId` 不同且旧记录在线 → 拒绝，`message="区 ID 已被其他进程使用"`，打印警告（区 ID、新旧 instanceId、新连接地址）。
  3. `instanceId` 不同且旧记录不在线 → 覆盖，接受。
  4. 某个区第一次出现、或换了 `instanceId` 时打印一行信息日志（区 ID、host、port、instanceId）；同一实例的定时上报不打印。
- `online(zoneId)`：记录存在、`session.getChannel().isActive()`、`当前时间 - reportTime ≤ 30 秒` 时返回该记录，否则返回 null。
- 记录不删除；断开连接（`ServerSessionInactiveEvent`）也不删除。

### 3.4 `LoginService`

```java
LoginReport logic = zoneService.online(DEFAULT_ZONE_ID);
if (logic == null) {
    throw new BusinessException("服务器维护中");
}
...
return new LoginResult(loginTicket, logic.getHost(), logic.getPort());
```

其余逻辑不变：仍然固定 1 区、票据写 `zoneId`、登录成功写 Redis `danmu:<appKey>:room:<直播间ID>`。

## 5. 验收项

| # | 场景 | 预期 |
| --- | --- | --- |
| 1 | 启动后查看 ZooKeeper | `/danmu/<appKey>/provider` 下有登录服节点，形如 `login-1 \| <内网IP>:12400 \| provider:[login-loginReport]`；没有 `/danmu/<appKey>/login`、`/danmu/<appKey>/logic` |
| 2 | 游戏服启动 | 登录服打印收到 1 区上报的日志，之后每 10 秒收到一次但不刷日志 |
| 3 | 1 区在线时登录 | 返回上报里的 `host`、`port` |
| 4 | 没有游戏服时登录 | 返回「服务器维护中」 |
| 5 | 游戏服停止 | 连接断开后立即视为不在线，登录返回「服务器维护中」；记录仍在表里 |
| 6 | 游戏服挂起（连接还在但不再上报）超过 30 秒 | 视为不在线 |
| 7 | 同一区号第二个进程上报 | 回复拒绝，打印警告；表里仍是第一个进程 |
| 8 | 1 区进程重启 | 新进程被接受，登录返回新地址 |
| 9 | 登录服重启 | 10 秒内（通常立即）恢复 1 区记录 |
| 10 | 部署两台登录服（`login-1`、`login-2`） | 游戏服两台都连上、都上报，两台都能正常分配 |
| 11 | 代码检查 | 没有 `ServiceDiscoveryService`、`ServerNode`；没有业务代码直接读写 ZooKeeper |
